# ModMe ↔ AgentOS Context Bridge

This file maps ModMe workspace vocabulary to the AgentOS (Agno) concepts used in
this platform so that any agent, coding-agent skill, or team member can reason
across both terminologies without ambiguity.

---

## Concept Mapping

| ModMe concept | AgentOS / Agno concept | Notes |
|---|---|---|
| **AgentSatellite** | `Agent` (`agno.agent.Agent`) | A focused, single-purpose agent with tools, memory, and a DB session. |
| **GenUIIsland** | Agent run returning a JSON layout schema | The agent (e.g. `genui-orchestrator`) emits a `layout_schema` array the Next.js route group renders. |
| **SchemaContract** | Tool return type + `render_dashboard` validator | Pydantic (backend) and Zod (frontend) enforce the same wire shape. |
| **ToolsetRegistry** | `app/registry.py` + `agno.tools.*` toolkits | The safe Studio registry exposes web-search, reasoning, and utility tools. |
| **GenUI orchestration step** | `Workflow` step (`agno.workflow`) | Deterministic, repeatable; maps user intent → component selection → schema emission. |
| **MCP interface / UI connector** | `/mcp` endpoint + `run_agent` MCP tool | CopilotKit or any MCP client calls `run_agent("genui-orchestrator", message)`. |
| **Inbox-driven knowledge capture** | Agent knowledge base (`create_knowledge`) | Pgvector-backed; documents land in `<table>_contents` and are searchable via hybrid RAG. |
| **lean-ctx / context handling** | `add_history_to_context`, `num_history_runs` | Controls how many prior turns the agent sees; tune per agent. |
| **multi-agent worktrees** | `Team` (`agno.team`) | Route/coordinate between specialist agents; wire through Studio or code. |
| **devcontainer** | `compose.yaml` (`agentos-api` service) | Hot-reload on `agents/`, `app/`, `db/`, `workflows/`; restart for dep/env changes. |

## GenUI Rendering Modes

The `genui-orchestrator` agent supports three modes:

- **STATIC** — fixed layout; ideal when the data shape is predetermined.
- **DECLARATIVE** — schema-driven; the frontend assembles components from a
  `layout_schema` JSON array at runtime using CopilotKit's `useCopilotReadable`
  / `useCopilotAction` hooks.
- **OPEN-ENDED** — freeform HTML rendered in a sandboxed iframe via the
  `SandboxedHTML` molecule; use only as a fallback.

### Available GenUI Molecules

| Molecule | Use case |
|---|---|
| `StatCard` | Single KPI value with optional trend |
| `DataTable` | Paginated, sortable table |
| `ChartCard` | Line / bar / pie chart |
| `SandboxedHTML` | Rich custom HTML layout |

## Schema Contract (wire format)

The `layout_schema` field returned by `genui-orchestrator` is a JSON array:

```json
[
  {
    "id": "StatCard",
    "props": {
      "title": "Monthly Revenue",
      "value": 124500,
      "unit": "USD",
      "trend": "up"
    }
  },
  {
    "id": "DataTable",
    "props": {
      "columns": [{"key": "name", "label": "Name"}, {"key": "value", "label": "Value"}],
      "rows": [{"name": "Widget A", "value": 42}]
    }
  }
]
```

The backend validates this with `render_dashboard(layout_schema)` before
returning it. The Next.js frontend should apply the same Zod schema derived
from the `SchemaContract` source of truth.

## Notes on Toolsets & Inbox Capture

- Add new tools to an agent by editing its file in `agents/` and restarting the
  `agentos-api` container (`docker compose restart agentos-api`).
- To add a knowledge base (inbox capture), call `create_knowledge("Label", "table_name")`
  from `db` and pass it to the agent's `knowledge=` parameter.
- The `ToolsetRegistry` pattern mirrors `app/registry.py` — add scoped tools there
  for safe Studio/Agent Builder access.

## modme-genui-bridge Skill

When building agents that emit GenUI-compatible state, follow these conventions:

1. **Always call `get_component_registry`** before composing a layout so the
   component IDs are grounded in the live registry.
2. **Always call `render_dashboard(layout_schema)`** to validate the schema before
   returning it — never emit an unvalidated schema.
3. **Return the schema in a fenced `json` code block** so CopilotKit's frontend
   parser can extract it by label.
4. **Use `add_history_to_context=True`** so the agent can refine layouts across
   multi-turn conversations.
5. **Extend `_COMPONENT_REGISTRY`** in `agents/genui_orchestrator.py` as new
   molecules land in the frontend library — the validator and prompt auto-update.
6. **Keep layouts ≤ 8 components**; use drill-down navigation for larger data sets.
